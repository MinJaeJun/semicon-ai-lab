# RelyLab — 신뢰성 불합격, 설계 마진인가 설비인가

FinFET 웨이퍼 1,200장의 소자 파라미터 · 신뢰성 시험 9,600건 · 설비 이력을 엮어
**불합격의 원인이 파라미터 마진인지 특정 설비인지** 가른다.

```bash
python generate.py   # 데이터 생성 + 검증
python analyze.py    # 파라미터 모델 → 설비 추가 → 설비 귀인
```

## 문제

신뢰성 시험에서 떨어졌을 때 두 가지 원인이 있다.

1. 소자 파라미터가 마진을 못 지켰다 → 설계/공정 조건 문제
2. 특정 설비가 파라미터로는 안 잡히는 방식으로 품질을 갉아먹었다 → 설비 문제

이 둘을 섞어 보면 엉뚱한 대책이 나온다. 설비 문제인데 스펙을 조이면 수율만 떨어진다.

이 데이터에는 **조용히 틀어진 설비 2대**를 심어뒀다 (`FURN-02`, `PVD-02`).
둘 다 자기 담당 파라미터를 **스펙 안에서만** 민다. 인라인 계측 판정으로는 안 잡힌다.

## 접근

### 1단계 — 파라미터만으로 얼마나 설명되는가

소자 파라미터 14개로 시험별 불합격을 예측한다. Lot 단위 GroupKFold.

### 2단계 — 설비를 넣으면 얼마나 좋아지는가

같은 모델에 설비 배정을 추가하고 AUC 차이를 잰다.
유의하게 좋아지면 파라미터로 안 보이는 원인이 설비 쪽에 있다는 뜻이다.

| 시험 | 불합격률 | AUC (파라미터) | AUC (+설비) | 개선 |
|---|---:|---:|---:|---:|
| HTOL | 0.184 | 0.894 | 0.948 | +0.054 |
| TDDB | 0.336 | 0.838 | 0.985 | **+0.147** |
| NBTI | 0.331 | 0.848 | 0.975 | **+0.127** |
| HCI | 0.235 | 0.867 | 0.949 | +0.082 |
| EM | 0.259 | 0.819 | 0.971 | **+0.153** |
| ESD | 0.311 | 0.832 | 0.942 | +0.111 |
| TC | 0.107 | 0.839 | 0.919 | +0.080 |
| LTOL | 0.196 | 0.868 | 0.943 | +0.076 |

평균 **+0.104**. 개선폭이 가장 큰 세 시험(EM +0.153, TDDB +0.147, NBTI +0.127)은
전부 문제 설비가 담당하는 모듈(M1 BEOL, Gate Oxide)에 민감한 항목이다.
신호가 엉뚱한 데서 온 게 아니라는 뜻이다.

### 3단계 — 어느 설비인가

**웨이퍼를 독립 표본으로 보면 안 된다.** 설비는 Lot 단위로 배정되므로
웨이퍼 1,200장을 그대로 검정에 넣으면 유의성이 과대평가된다.
Lot 평균으로 집계한 뒤 Mann-Whitney U 단측 검정을 돌린다.

| 모듈 | 설비 | Lot 수 | 합격률 | 타 설비 | 차이 | 플래그 | 실제 |
|---|---|---:|---:|---:|---:|:---:|:---:|
| Gate Oxide | `FURN-02` | 29 | 0.308 | 0.844 | **−0.537** | O | **O** |
| M1 BEOL | `PVD-02` | 23 | 0.311 | 0.712 | **−0.401** | O | **O** |
| Contact | `ETCH-05` | 28 | 0.423 | 0.656 | −0.233 | O | − |
| HK/MG | `ALD-02` | 22 | 0.413 | 0.611 | −0.198 | O | − |

15대 검정 → 4대 플래그. **recall 1.00 / precision 0.50**.

주목할 점은 **효과 크기가 확실히 갈린다**는 것이다. 진짜 문제 설비 2대는 차이가
−0.40, −0.54 이고 p 값이 3.4e-4, 3.0e-6 이다. 오탐 2대는 차이가 −0.20, −0.23 이고
p 값이 0.038, 0.044 로 겨우 유의선을 넘겼다.

p < 0.05 만으로 자르면 오탐이 절반이다. 실무에서는 **효과 크기 하한(예: 차이 0.3 이상)**
을 같이 걸어야 하고, 그러면 정확히 2대만 남는다. 표본이 Lot 48개뿐이라 생긴 한계이고,
실제 현장이라면 바로 조치하지 않고 추가 Lot 을 모아 재검정한다.

## 왜 파라미터 판정으로는 못 잡는가

| 설비 | 모듈 | 파라미터 | 스펙내 비율(해당) | 스펙내 비율(타) | 신뢰성 합격률(해당) | (타) |
|---|---|---|---:|---:|---:|---:|
| `FURN-02` | Gate Oxide | `gate_ox_thk_nm` | 0.755 | 0.931 | **0.308** | 0.844 |
| `PVD-02` | M1 BEOL | `m1_width_nm` | **0.983** | 0.998 | **0.311** | 0.712 |

`PVD-02` 를 보면 파라미터 스펙내 비율이 **98.3%** 다. 타 설비(99.8%)와 1.5%p 차이뿐이고,
인라인 판정으로는 **완벽한 정상 설비**다. 그런데 신뢰성 합격률은 31% 로 타 설비 71% 의
절반 아래다.

설비 배정 이력과 신뢰성 결과를 엮어야만 드러난다. 이게 이 프로젝트의 결론이다.

### 소자 파라미터 (5nm 급, 합성)

```
fin_width_nm, fin_height_nm, gate_length_nm, gate_ox_thk_nm, hk_thk_nm,
sd_epi_thk_nm, contact_cd_nm, m1_width_nm, m1_space_nm, via_cd_nm,
vt_n_V, vt_p_V, idsat_uA_um, ss_mV_dec
```

각 파라미터에 `__in_spec` 판정 컬럼이 붙어 있다.

### 신뢰성 시험

HTOL · TDDB · NBTI · HCI · EM · ESD · TC · LTOL
시험마다 민감 파라미터가 정해져 있다 (예: TDDB ← gate_ox_thk / hk_thk / gate_length).

### 공정 모듈 ↔ 설비

```

Via         ETCH-06/07
```

설비는 Lot 단위로 배정된다. 실제 팹 디스패치와 같다.
